A.1–A.7 · Documentos maestros

Siete estándares, un solo contrato.

Haz clic en cada estándar para expandir sus reglas clave. Cada uno tiene su documento .md como fuente de verdad.

  • Herramientas: Jest + jest-expo (móvil) · Vitest (PWA/shared) · Maestro (E2E móvil) · Playwright (E2E PWA).
  • Cobertura: ≥80% líneas/ramas en negocio; 100% de escenarios en flujos críticos (vault, export/import, dinero).
  • TDD estricto en domain/, application/, shared/export-contract y dinero en centavos.
  • DoD: código + tests + i18n + a11y + 4 estados + flag (si aplica) + 1 aprobación.
  • Fixtures: matriz de ficheros .monedero (v1, corrupto, futuro, hash alterado) en ambas apps.
  • Idiomas: es-CO por defecto (mercado inicial) y en-US (fase 1). Fallback: en-US → es-CO → clave.
  • Claves: dominio.pantalla.elemento.variante en JSON por idioma, plurales _one/_other.
  • Montos: único módulo formatMoney(amountCents, currency, locale) — COP 0 decimales, USD/EUR 2.
  • Test de expansión +30% (simulado de-DE) sin desbordes en CTAs ni cifras.
  • Códigos de error de dominio → mensajes localizados en errors.*; el código crudo solo se loguea.
  • Contraste verificado: primary 5.0:1 · accent-text 4.8:1 · muted 4.6:1. Terracota #D97757 solo gráfico; placeholder nunca como única etiqueta.
  • ARIA matrix obligatoria: tablist, dialog + focus trap, live regions para toasts, aria-invalid + aria-describedby en errores de campo.
  • Objetivos ≥44px, focus-visible 3px, zoom 200%, sin parpadeo.
  • Lectores: VoiceOver, TalkBack, NVDA/JAWS. Cifras anuncian moneda y signo.
  • Gates: axe-core (PWA), jest-axe, test de props RN, keyboard E2E.
  • Logger local en ring buffer cifrado: ts, level, traceId, screen, event, code. Nunca importes, textos ni passphrases.
  • Error tracking local: ErrorBoundary + handler global → últimos stacks en Diagnóstico; export .log.json bajo decisión del usuario.
  • Perf local: Web Vitals en buffer + marcas móviles; presupuestos (arranque <1,5 s, alta <300 ms).
  • Gate no-network: E2E que falla el build si hay cualquier fetch externo en producción.
  • Prohibidos: Sentry, LogRocket, analytics, SDKs con red.
  • GitHub Flow: main siempre desplegable; ramas ≤3 días; squash merge.
  • Scopes canónicos: mobile, pwa, shared, contract, ds, i18n, a11y, ci, docs.
  • Hooks: husky + lint-staged + commitlint; 2 aprobaciones si toca shared/contract o vault.
  • PR template obligatorio con secciones de testing, a11y, i18n, evidencia visual y flags.
  • Releases SemVer por app: mobile@x.y.z · pwa@x.y.z.
  • Sin SaaS (requieren red): flags en packages/flags con isFlagEnabled() único punto de acceso.
  • Nombres: <ámbito>.<funcionalidad>.<versión> — ámbitos feature/experiment/ops/env.
  • Ciclo de vida: cada flag con HU y fecha; flags:lint falla CI a los 90 días; eliminar flag ⇒ eliminar código muerto.
  • Prohibidos flags en shared/contract. Tests de ambos caminos mientras exista.
  • Regla de inyección: por pantalla, cargar solo blueprint + componentes DS usados + contrato/entidad + reglas a11y/i18n. Nunca la documentación completa.
  • Índice: mapea BP-01…BP-10 y F6 a sus chunks, historias, flags y estados obligatorios.
  • Gates CI globales declarados en el índice: typecheck, lint, test, a11y, tokens, contract, network.
A.4/A.6 · Decisiones de coherencia con ADR-001/002

Adaptaciones deliberadas (requieren tu aprobación).

La skill asume por defecto telemetría y flags en la nube. Monedero es 100% local, cero red, cero telemetría: imponer esas herramientas violaría las decisiones ya aprobadas. El Auditor registra la sustitución:

📡 Observabilidad

✗ Sentry + LogRocket + alertas Slack
✓ Logger JSON local + export de diagnóstico bajo demanda del usuario

Sin red no hay error tracking remoto. El «usuario-soberano» decide si comparte un .log.json cifrado. Alertas = avisos in-app. Gate no-network garantiza el aislamiento.

🚩 Feature Flags

✗ LaunchDarkly / Unleash
✓ Solución propia: build-time (env) + runtime en settings local

Los proveedores SaaS requieren red. La solución propia cubre lanzamientos y rollback rápido por rebuild, con ciclo de vida anti-deuda (90 días, ≤8 activos).
